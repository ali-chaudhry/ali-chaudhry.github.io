Project 1

Real-Time VGA Pong Game

Oct 2026 – Nov 2026 VHDLXilinx Spartan-3EXilinx ISEChipScope Pro

What it is

A two-player Pong game built entirely in digital hardware. There is no processor or software: every pixel on the screen is produced by logic I described in VHDL and loaded onto the FPGA.

Video
640×480 at 60 Hz VGA, 8-bit red, green and blue
Clocking
25 MHz pixel clock divided from the 50 MHz board clock
Device
Xilinx Spartan-3E XC3S500E
Controls
Four on-board switches, up and down for each paddle
Verified
On hardware with the ChipScope Pro integrated logic analyzer

What I did

  • Designed the VGA timing chain: a clock divider, horizontal and vertical pixel counters, and a sync generator that produces the h_sync and v_sync signals the monitor locks onto.
  • Wrote the game logic for the paddles and ball, including ball motion, collisions with the borders and paddles, and goal detection. Positions update once per frame on a new_frame pulse, so motion stays smooth and in step with the display.
  • Built a rendering block that decides each pixel's colour from the counter position and the object positions.
  • Integrated all modules in a top-level schematic in Xilinx ISE, assigned pins, and brought the design up on the board.

Skills demonstrated

  • RTL design in VHDL: counters, clock division, synchronous logic, modular interfaces
  • Standard VGA video timing generated from first principles
  • FPGA tool flow: schematic and HDL entry, pin constraints, synthesis, programming
  • On-chip debugging with an integrated logic analyzer

Simulation shows the logic is correct; it does not show the design works on real hardware. Capturing the clock, sync and colour signals directly from the FPGA while the game ran let me confirm the VGA timing on the actual device instead of relying on the monitor picture alone.

Project 2

32-bit CPU Design & Verification

Jan 2026 – Apr 2026 VHDLIntel Quartus PrimeAltera DE2-115

What it is

A 32-bit CPU built up in VHDL over a term of Computer Organization and Architecture, working with a lab partner. The datapath, control unit and synchronous reset circuitry were designed as separate blocks, then integrated into one processor.

What I did

  • Designed and integrated the datapath and control unit into one working processor.
  • Implemented synchronous reset logic that initializes the Program Counter and puts the CPU in a known, stable state before the first instruction.
  • Wrote the control unit as a state generator, an operation decoder and memory control logic, so every instruction executes over three clock cycles.
  • Ran timing simulation and functional verification of instruction fetch, ALU operations, control behaviour and memory access.

How the control unit works

It reads the current instruction and produces the synchronous control signals that drive the datapath: register load and clear signals, the 3-bit ALU operation code, the multiplexer selects, and the memory enable and write signals.

Load / store
LDA LDB LDAI LDBI LUI STA STB
Arith / logic
ADD ADDI SUB AND ANDI ORI INCA DECA
Rotate / clear
ROL ROR CLRA CLRB CLRC CLRZ
Jump / branch
JMP BEQ BNE

Verification

Each instruction was simulated in Quartus and its control signals checked state by state: 22 instruction waveforms in total.

Skills demonstrated

  • Processor architecture: datapath and control unit design
  • FSMs and instruction decoding in VHDL
  • Turning a control signal table into working RTL
  • Timing simulation and waveform analysis

Project 3

Autonomous Maze-Solving Robot

Sept 2025 – Nov 2025 HCS12 AssemblyAdapt9S12CEEBot

What it is

A small mobile robot that finds its way through a line maze with no outside control, programmed entirely in HCS12 assembly language, working directly with the microcontroller's sensors, motors and interrupts.

What I did

  • Integrated the guider (line) sensors, bumpers and motor control into one program.
  • Designed a finite state machine covering line following, obstacle avoidance and autonomous recovery.
  • Used interrupt-driven sensor scanning so readings stay current while the motors are controlled in real time.

Skills demonstrated

  • Low-level embedded programming in assembly
  • Finite state machine design for real-time control
  • Interrupts, sensor interfacing and motor control
  • Testing and tuning on physical hardware
